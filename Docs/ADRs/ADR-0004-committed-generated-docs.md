# ADR-0004 — Generated API docs are committed and gated against the module inventory

Status: Accepted
Date: 2026-11-09

## Context

`Docs/api-reference.md` and `Docs/API/*.md` are generated by
`Modules/Documentation.psm1` (`Show-GBuildHelp -Modules`). They are committed so
a reviewer can read the API without running the tool.

For most of 2026 they were stale. The cleanup that deleted
`Alerting.Invoke-BuildSecretProtect` (one of four historical copies) left it
documented, and the new `Alerting.Get-AlertRotationHours` was missing. The tree
was 70 functions and 2 pages behind the modules, and nothing compared the two.

## Decision

The generated docs are committed, and `Tests/Documentation.Tests.ps1` regenerates
them into a temp directory on every run and fails on **any** diff — the index,
the page set, and every page's content.

The docs are generated from an absolute `Modules` directory so the `Source:`
line is a stable repository-relative path (`Modules/<Module>.psm1`), never a
machine-specific absolute path.

## Consequences

- A change that adds, renames, or deletes a function must refresh the docs in
  the same change. The gate fails otherwise.
- The docs must never be hand-edited; the header says so and the gate enforces
  it.
- The generation cost is one extra parse pass per Documentation scope run.

## Evidence

- `Modules/Documentation.psm1` (`New-ModuleDocumentation`, `Show-GBuildHelp -Modules`)
- `Tests/Documentation.Tests.ps1` (the sync gate)
- `Docs/api-reference.md` and `Docs/API/` (72 pages, 1,089 functions)
